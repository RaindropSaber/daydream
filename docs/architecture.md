# 架构与数据库

## 应用进程

Next.js App Router 提供 React 页面、`/api/` JSON 接口及 `/media/` 文件读取。`scripts/server.ts` 启动一个 Node HTTP 服务，并运行持久化任务队列。Tailwind CSS 4 提供样式，表单、弹窗、选择器和表格采用 shadcn/ui。浏览器使用 React 状态和组件，无旧版脚本或嵌入页面。

SQLite 由 Node 内置的 `node:sqlite` 直接读写，无需独立数据库服务、Python API 或 Vite 服务。FFmpeg 是按任务启动的原生子进程，负责视频探测、裁切、画幅归一、音轨补齐、拼接、音频提取和字幕烧录，退出应用时终止子进程。

## 页面路由

页面由 Next.js App Router 的实际目录定义，`(studio)/layout.tsx` 共享确认弹窗和创作助手会话。页面参数由服务端路由传入工作台，导航统一通过 `src/lib/studio-routes.ts` 生成路径。

- `/`：公开产品首页；`/?login=1`：首页并打开登录弹窗。
- `/workspace`：当前账号的项目列表；`/models`：当前账号的模型管理；`/account`：账户名、只读手机号和密码设置。
- `/admin`：管理员审核、账号管理和管理员授权；`/admin/setup`：首次管理员初始化页面，仅在系统没有管理员时可完成设置。
- `/projects/[projectId]`：项目视频制作首页。
- `/projects/[projectId]/stories`、`assets`、`jobs`、`models`：项目故事创作、素材库、任务记录和模型管理。
- `/projects/[projectId]/episodes/[episodeId]`：直接打开分集，默认展示已完成方案或当前方案，并定位其制作进度。
- `/projects/[projectId]/episodes/[episodeId]/[step]`：分集的指定制作步骤。
- 分集页面可追加 `?run=[runId]&version=[versionId]`：选择方案和草稿版本；省略时使用默认方案和版本。

项目、分集和制作步骤定义页面层级，使用 path；方案和草稿版本是页面内的内容选择，使用 query，筛选、排序等附加状态也可使用 query。旧的 `?view=...&project=...` 页面入口不再解析。无效步骤返回 404；分集或方案不存在时明确提示，不回退到其他资源。API 查询参数（例如刷新模型列表）继续按各接口的语义使用。

手机号首次登录填写用户名称后创建待审核的 `users` 记录。`access_status` 取值为 pending、approved、rejected、disabled，`role` 区分 member 和 admin。只有 approved 账号可获得或使用会话；后续登录验证密码哈希，`user_sessions` 保存会话摘要。审核通过/拒绝、停用/恢复在事务内进行，`user_access_reviews` 记录操作者及状态变化；停用时注销会话。首个管理员可通过首次初始化页面设置：服务启动时仅在没有管理员的情况下签发随机口令，数据库只保存摘要和有效期，本机凭据文件权限为 0600。初始化在事务内验证系统仍无管理员、口令未使用且未过期，完成后自动登录并关闭初始化入口。后续管理员可在后台将已通过的普通用户设为管理员；服务器命令 `admin:create` 同时保留。`admin_role_events` 统一记录服务器命令、首次初始化和管理后台的角色授权，包含操作来源及后台授权人。迁移保留已有服务器授权历史。历史 `admin_setup_tokens` 表保留但不再参与认证。业务 API 使用请求账号上下文限制项目与模型配置，后台任务从项目所属账号恢复上下文；媒体通过 `media_owners` 校验所属账号。旧工作区记录保留，不自动分配到新手机号。

## SQLite 实体

| 表                                    | 用途                                                         |
| ------------------------------------- | ------------------------------------------------------------ |
| `projects`                            | 项目名称与简介                                               |
| `production_settings`                 | 每项目一份视频视觉风格、画幅、美术规范、改编要求与独立修订号 |
| `stories` / `story_revisions`         | 每项目一部长篇、章节草稿与定稿、引用章节内容的不可变修订清单           |
| `story_chapter_contents` | 按内容摘要去重的不可变章节载荷，避免每次修订复制全书正文 |
| `novel_tasks` | 独立长篇任务的状态、执行令牌、写作进度与分卷检查断点 |
| `episodes`                            | 项目内分集与当前制作方案                                     |
| `production_runs`                     | 制作方案、模型及视频选项                                     |
| `content_versions`                    | 各创作阶段的不可变内容版本、上游依据和确认状态               |
| `selected_versions`                   | 每个阶段当前采用的版本                                       |
| `assets` / `asset_versions`           | 项目素材库及其版本                                         |
| `conversation_messages`               | 分阶段对话及生成稿关联                                       |
| `media_versions` / `media_selections` | 片段视频候选及当前采用结果                                   |
| `exports`                             | 导出文件、字幕、裁切快照和输入依据                           |
| `jobs`                                | 队列状态、远端任务 ID、输入快照、进度和批次子任务            |
| `settings`                            | 加密的模型配置                                               |
| `legacy_imports`                      | 旧数据快照指纹和导入报告                                     |
| `runtime_locks`                       | 后台执行器进程与持有令牌                                     |
| `schema_migrations`                   | 已应用的 SQL 迁移                                            |

实体关系使用外键，版本序号有唯一约束。内容和任务快照中的动态结构使用 JSON 文本；并非将所有项目塞进一个 JSON 文档。制作方案复制时保留版本身份，因此内容版本和媒体版本的主键包含方案 ID。

项目写入使用 `BEGIN IMMEDIATE` 事务，并在进程内串行调度数据库操作；异步调用共享当前事务，避免并发编辑覆盖或生成相同版本序号。版本内容追加保存，采用指针单独更新。当前数据访问以项目为聚合边界；读取项目会装配其分集和历史版本，适用于当前本机工作区规模。

## 创作与结果规则

项目只包含名称与简介，项目内并列「视频制作」和「故事创作」。视觉风格、画幅、美术规范与改编要求以 `production_settings` 独立保存，由 `Project.production` 读取。项目名称/简介的更新不改变制作依赖；制作设置使用独立修订号校验并发，只使未锁定、未结束的视频方案待更新。结束方案保存自己的制作设置快照，使原导出依据保持有效。

每个项目只有一部故事，包含顺序章节；故事创作不绑定视频分集、方案、模型或目标时长。故事保存采用修订号并发校验，每次保存保留不可变修订；章节正文、标题或提要修改后回到草稿，显式定稿后才可被选用。

视频流程为故事选章、分镜与资源、视频生成、合成导出。故事阶段只能选择本项目已定稿章节，服务端按作品顺序构建正文、章节身份、作品修订与世界人物设定的快照，不能通过手写或助手生成故事。原文更新不修改视频已有快照；重新选章会创建新的制作依据并使相关下游待更新。修改视频配置只影响制作阶段，不影响故事来源。草稿、采用和确认分别保存；生成新候选不会替换用户已经采用的视频。上游内容改变会使下游状态变为待更新，历史版本和文件仍可查看。

视频有效性依据片段提示词、节拍、设定、模型、选项和续写上游版本计算。修改单段不会无故废弃无关片段。整集生成先计算可复用片段和新增时长，确认后保存输入快照；完成后仍需采用整集结果。

## 素材采用与引用

素材版本保持不可变。`draft_versions` 按剧情状态记录当前可编辑设定，`adopted_versions` 记录该状态的采用图；`selected` 表示素材整体的默认版本。文字保存、生成候选和上传候选均不自动改变已采用图片或现有分镜引用。采用图片与更新引用是独立操作。

更新引用在项目事务中检查当前资源版本、方案状态及运行中任务；只为用户所选的可编辑方案创建资源草稿，不修改历史版本、已结束方案或未选中的方案。媒体文件上传使用同源校验、登录及项目归属检查，限制PNG/JPEG和20MB，结果保存为候选。

## 持久化任务

任务保存于 SQLite。执行器在事务中登记进程 PID 和随机令牌，保证同一个数据库文件只运行一个 worker；活跃进程持有记录时其他执行器不接管，崩溃后检查原进程已退出才能恢复。领取任务使用单条 `UPDATE … RETURNING`，原子地更新队列状态。重启后运行中的任务标记中断，保留结果和远端 ID；带远端 ID 的视频可继续查询原任务。

视频提交前持久化 `submit_attempted`，获得远端 ID 后立即保存。提交超时且没有 ID 时不会自动重新提交。整集任务保存子任务及完成结果，恢复时复用已完成片段。生图逐姿态保存结果和提交记录，避免将不确定提交静默重试。失败提示要求核对供应商控制台时，需要先核对实际计费和任务结果。

外部模型适配包含方舟文本、Seedance 视频、Seedream 生图和万相视频。字幕用音频识别或台词对齐服务产生时间轴，再由 FFmpeg 烧录和输出 SRT。供应商接口真实可用性和账户模型权限取决于实际配置；自动测试模拟外部响应。

## 数据与本机边界

密钥在服务端加密保存，API 不返回原始密钥或任务私有输入快照。API 校验主机及同源请求。媒体路由限制在数据媒体目录内，支持视频 Range 读取。服务仅监听回环地址；提供账号隔离与管理员审核，尚未提供完整的公网部署流程。

`DATA_DIR` 默认为用户主目录的 `~/.daydream/`，数据库默认为其中的 `frameflow.sqlite3`，可用 `SQLITE_PATH` 指定其他文件。SQLite 开启 WAL、外键约束、完整同步与繁忙等待。版本化建表脚本位于 `db/sqlite-migrations/`；`db/migrations/` 中的 PostgreSQL 脚本仅保留历史参考。

启动命令应在项目根目录运行。备份需同时保留数据库、媒体和 `.encryption-key`；离线复制前停止应用，或使用 SQLite 在线备份，避免遗漏 WAL 中的数据。

旧版 SQLite 导入只读原文件并先生成一致性备份。PostgreSQL 迁回工具读取只读一致性快照，将所有实体和加密配置导入空的 SQLite 文件，并逐表核对内容与外键。原数据库、旧文件及备份保留，运行时只使用 SQLite；`DATABASE_URL` 仅供迁移工具使用。


长篇任务由主任务进程持有运行锁后启动独立调度器，与视频队列并行。每次只执行一个规划、正文、记忆或审校步骤，模型调用在事务外执行，提交时核对任务令牌和作品修订。自动写作期间手动保存受保护；暂停后可以编辑。章节内容按摘要去重保存在 `story_chapter_contents`，`story_revisions` 保留章节引用清单；`loadStoryRevision` 解析不可变历史修订。当前 `stories.data` 保留完整工作副本，便于阅读、编辑与导出。

账户设置 API 始终从会话解析用户身份，不接受客户端指定账号。账户名更新只允许 username 字段；手机号和权限字段不可修改。改密验证原密码、限制错误尝试，使用事务比较旧密码哈希并注销该账号全部会话。登录签发会话前再次检查密码哈希，避免并发改密后仍签发旧凭据会话。
