# 备份、恢复与迁移

[返回文档索引](README.md)

## 工作区包含什么

默认工作区为项目根目录的 `data/`，主要包含：

- `frameflow.sqlite3`：项目、内容版本、任务、素材索引及加密配置。
- `media/`：设定图、视频和导出文件。
- `.encryption-key`：解密已保存模型配置所需的密钥。
- `backups/`：导入工具生成的备份。

数据库保留 `frameflow.sqlite3` 名称以兼容早期工作区。重命名项目不会移动或重命名已有数据。使用了 `DATA_DIR`、`SQLITE_PATH` 或旧版媒体路径时，应把实际位置一起纳入备份。

## 备份

1. 用 Ctrl+C 停止应用，等待进程退出。
2. 复制完整工作区目录，包含隐藏的 `.encryption-key` 文件；若数据库在工作区外，另行复制数据库及其同目录残留的 `-wal`、`-shm` 文件。
3. 单独保存需要保留的 `.env.local` 等本机配置，并记录自定义路径。
4. 将备份保存在可信位置；数据库、历史导入备份和环境配置可能包含凭据或私人创作内容。

运行中的 SQLite 可能仍有未合并的 WAL 数据，不要仅复制运行中的主数据库文件。需要在线备份时，应使用 SQLite 在线备份机制，并另行保留媒体与加密密钥。

Git 仓库只保存源码，不能代替工作区备份。应用不会自动替你安排定期备份。

## 恢复或换电脑

1. 在目标电脑获取源码并安装依赖，满足 Node.js 22.16+ 要求。
2. 确保应用未启动，将工作区、密钥和必要的本机环境配置恢复到目标位置。
3. 如目录发生变化，调整 `DATA_DIR`、`SQLITE_PATH` 及其他自定义路径。
4. 执行 `npm run dev`，或完成构建后运行 `npm start`。
5. 检查项目列表、已有媒体及模型连接是否正常。

不要混合不同时间点或不同工作区的数据库与密钥。只有数据库而没有对应 `.encryption-key` 时，无法解密原先保存的模型配置。旧媒体若仍指向原位置，也需要保留或迁移相应文件。

## 从早期 SQLite 工作区导入

适用于仍使用 `data/studio.sqlite3` 的旧版数据，不是日常启动必需步骤。停止旧应用，并先备份原工作区，然后运行：

```sh
npm run db:import
```

导入器从旧数据库导入项目、分集、制作方案、内容版本、资源、对话、任务和导出记录，并从 `data/seedance.json` 读取旧模型配置后加密保存。导入前创建一致性备份，原数据库、配置及媒体保留。

重复导入同一快照不会重复创建记录；同 ID 的不同快照拒绝覆盖。媒体保留原路径。无法核验的历史媒体会保留为待审阅，导入后请检查素材与成片状态。

## 从旧版 PostgreSQL 导入

此步骤只适用于已有 PostgreSQL 版本工作区。正常运行不依赖 PostgreSQL。

1. 停止旧应用，保留原 PostgreSQL 服务运行，先备份原工作区。
2. 在本机环境配置中设置原 `DATABASE_URL`，不要把真实连接字符串提交到仓库。
3. 使用空的目标 SQLite；必要时通过 `SQLITE_PATH` 指定一个新文件。
4. 执行：

```sh
npm run db:import:postgres
```

工具读取只读一致性快照并写入 `data/backups/`（或自定义工作区的 `backups/`），在事务中导入目标 SQLite，逐表核对内容并检查外键。目标已有数据时拒绝覆盖；导入失败会回滚目标写入。

导入后保留原 `.encryption-key` 和媒体文件，检查模型配置能否解密、历史素材能否读取。确认结果后即可停止原 PostgreSQL 服务；日常启动不读取 `DATABASE_URL`。历史快照和备份可能含敏感配置，请妥善保管。
