# 创作流程与助手协作

项目内有两个并列模块：侧栏先是「视频制作」，下方是「故事创作」。每项目一部故事，作品下有多个章节；视频下有多个分集和制作方案。

长篇流程为「一句想法与篇幅 → 全书方案和分卷 → 近期章纲 → 逐章正文与累计记忆 → 分卷检查和全书检查 → 用户确认完结」。全书方案从全局创作浮窗生成 `propose_novel_plan` 候选卡片，应用后才创建或更新作品；连续写作、恢复和全书检查先在浮窗准备 `prepare_novel_task` 操作卡片，应用后启动后台任务。后台任务使用故事 skill 和 `deliver_novel_step`；结果校验通过后逐步保存，不需要用户反复发送续写请求。近期计划每次最多五章，单章正文校验篇幅；上下文只带全书依据、上一章累计记忆、近章摘要和前章结尾，不发送全部正文。

`novel_tasks` 持久化排队、执行、暂停、失败和完成状态，以及剩余章数、已写章数、检查进度和执行令牌。暂停使旧令牌失效，未完成步骤不写入；提交同时核对作品修订，避免覆盖并发编辑。服务重启恢复为暂停；用户可继续。手动改动正文或设定后，受影响的剧情记忆失效，后台先逐章重建；发现冲突暂停并保留问题，不自动改写正文。全书检查先逐卷进行，再汇总；有待处理问题时不能确认完结。

手动故事助手使用 `propose_story_edit` 返回当前阶段候选稿，不保存、不定稿。应用前检查编辑快照；用户保存后形成作品修订。章节定稿后才能被视频选用，后台写作不会自动定稿。

视频流程为「分集大纲 → 选择本项目故事章节 → 分镜与资源 → 生成与审阅 → 合成导出」。故事环节只选择原文，服务端验证项目归属、作品修订与章节定稿状态，按原文顺序保存快照；不提供故事生成、手写保存或故事草稿工具。原作品更新不自动覆盖视频依据，用户重新选章才更新下游依赖。

全部创作入口共用右下角全局浮窗，包括全书方案、章节创作、连续写作、全书检查、分镜生成、素材匹配和镜头优化。分镜与素材候选应用前校验当前编辑快照，不再生成后直接覆盖页面。视频创作模块可以手动编辑，或使用「AI 生成」「与助手讨论」。助手查阅相关内容后生成可预览、可应用的结果卡片，应用后仍需保存、采用和确认。

新建和编辑项目只包含名称与简介，`project` 技能仅开放这两个字段。视频制作的「制作设置」使用独立 `production` 技能，只开放 style、ratio、prompt（美术规范）和 adaptation（改编要求）。故事主题、世界与人物归故事创作管理；项目简介不是剧情或视频指令。修改制作设置仅影响进行中的视频方案，不改故事与已选原文；修改简介不影响制作有效性。

## 输入模块、skill 与 tool 清单

| 流程 | 用户输入模块 | skill | 允许的表单 tool |
| --- | --- | --- | --- |
| 项目 | 名称与简介 | `project` | `update_project_form` |
| 视频制作设置 | 视觉风格、画幅、美术规范与改编要求 | `production` | `update_production_form` |
| 分集大纲 | 集名、本集剧情 | `episode` | `update_episode_form` |
| 制作方案 | 方案名称 | `run` | `update_run_form` |
| 故事创作（项目内） | 想法、目标篇幅、全书方案、当前章 | `story` | 手动 `propose_story_edit`；后台 `deliver_novel_step` |
| 视频故事选章 | 本项目已定稿章节 | 无生成技能 | 无生成工具 |
| 分镜与片段 | 整体导演意图、时间节拍、生成片段 | `director` | `update_director_form` |
| 镜头细化 | 当前节拍的画面、运镜、对白 | `beat` | `update_beat_form` |
| 视频提示词 | 当前片段的完整提示词 | `segment` | `update_segment_form` |
| 设定集 | 世界观与全部重要设定 | `settings` | `update_settings_form` |
| 世界观 | 时代、科技、美术、材质、配色、避免元素 | `world` | `update_world_form` |
| 单项设定 | 当前人物、场景或道具的描述 | `entry` | `update_entry_form` |
| 素材库 | 当前资源名称与描述 | `asset` | `update_asset_form` |
| 合成导出 | 已有有效视频的顺序和裁切 | `finish` | `update_finish_form` |

生成与审阅阶段的素材地址、首帧、声音、模型、分辨率、候选结果选择，以及导出的字幕方式等，由用户选择真实资源或确定参数。AI 可通过跨阶段助手讨论建议；这些选择不通过文本生成工具自动执行。生图、视频生成和成片导出的页面按钮统一打开全局浮窗中的任务卡片，列明参数与计费说明；用户执行后才提交任务，进度也在浮窗内展示。保存、采用、手动编辑等普通操作保留直接入口。

助手只显示一行会话选择、新建与收起按钮，以及聊天记录和自适应高度的输入框。新建会话记录为空，不显示绑定模块的状态说明，不继承其他会话的历史消息。当前项目与任务表单作为可按需读取的资料来源，内容不直接拼进初始消息。会话选择保留当前方案的历史对话入口；历史对话仍属于其原方案，需由用户主动选择。

## 同一个助手的两类写入

- **提示词驱动的新会话**：AI 入口预填提示词，统一调用 `/api/studio/assistant` 的 `prompt` 模式。显式 skill 标签优先加载；未加标签时 agent 可从 `load_creation_skill` 的技能目录选择并加载任务所需技能，下一轮开放其结果卡片工具。后续反馈未重选 skill 时保留本会话最近明确的任务技能。请求携带 `context_scope` 作为项目定位范围、`form_source` 作为当前未保存表单的读取来源；agent 通过只读工具自行取资料，无需用户手动引用。新分集仅使用项目范围，不把背后旧方案当作本集目标；旧方案的已结束状态不妨碍读取前情或生成新分集。生成结果只在技能与原表单匹配且快照有效时允许应用。
- **跨阶段创作对话**：保留分集／制作方案的共享持久化对话，读取已选故事快照、加载分镜和设定集 skills，使用同一个 `runCreationAgent`。讨论返回自然语言，明确需要草稿时调用 `save_stage_draft`；服务端继续执行前置阶段校验、内容校验、版本依赖校验，并保存一份待采用版本。不会切换用户的采用版本。

这两类写入共享模型连接、skill 文件和工具执行器，但保存边界不同：新会话只生成待应用卡片，历史跨阶段对话生成可追溯的版本草稿。新会话在当前工作区内独立保留，可通过会话选择切换；关闭原表单后仍可继续聊天和查看卡片，但不能向已关闭表单应用结果。

## 回填与校验

工具名和参数 schema 由服务端固定，模型不能指定任意字段、SQL、文件写入或其他动作。项目工具仅改名称与简介；制作设置工具可改画幅；单片段工具只改提示词；资源工具不编造 URL 或绑定；剪辑工具只使用当前有效媒体并校验实际时长。导演方案和完整设定集复用现有业务校验。

回填前比对当前表单与请求时的快照，以及局部上下文；用户在等待期间修改内容时，旧结果不会覆盖。组件卸载或切换到其他模块后，卡片不能应用到新的表单。应用后仍由用户保存。生成中再次点击会被拦截，失败保留原有内容和错误信息。

## 扩展新的协作模块

1. 在 `skills/creation/` 增加任务专用 `SKILL.md`，描述创作原则和修改边界。
2. 在 `src/lib/creation-flow.ts` 注册模块、skill 和固定工具名，并补充流程清单。
3. 在 `FORM_SCHEMAS` 定义最小字段白名单，在 `assistForm` 补充必要的前置和业务校验。
4. 在对应编辑组件接入 `FormAssistant`，传入当前表单、必要局部上下文及回填方法；回填仅修改本地草稿并标记未保存。
5. 验证讨论不写入、正确回填、越权工具／字段拒绝、前置条件和版本保留。测试模拟模型响应，不调用付费服务。

## 读取工具与依据

所有模块 skill 都描述了应参考哪些环节以及上游失效时如何处理。新会话和历史跨阶段助手按任务自行使用项目只读工具，不要求用户先引用或总结。新会话另有技能加载和当前表单读取工具。

| 工具 | 返回内容 |
| --- | --- |
| `load_creation_skill` | 按任务选择并读取白名单技能说明，开放对应结果卡片工具 |
| `get_current_form` | 当前未保存表单、目标时长及局部编辑依据；无表单时返回 exists=false |
| `get_project_context` | 项目名称与简介、视频制作设置、分集与方案目录；新项目返回 exists=false |
| `get_workflow_status` | 各环节 empty/draft/approved/stale 状态、选中/最新版本 ID、锁定与结束状态、近期任务状态 |
| `get_stage_content` | 指定环节版本目录、选中稿、当前有效已确认稿、最新草稿、指定历史版本；generation 包含真实片段、时长和有效性，finish 包含导出记录 |
| `get_project_assets` | 素材库及真实版本引用 |

读取限定在当前项目，支持按目录中的 episode_id/run_id 查询其他分集/方案。selected_version 不等于已确认；只有当前状态为 approved 时 approved_version 才有值。stale 内容保留供比较，不能当作有效上游。当前表单与局部上下文中的未保存编辑优先保留，冲突需解释或澄清。

新会话每轮最多十二次串行读取，其他入口默认六次，之后至多一次修改，修改后只回复说明。生成任务要求模型调用工具后交付结果；明确讨论和缺少真实素材的剪辑任务允许仅回复说明。模块助手读取实时项目，跨阶段任务读取提交时的项目快照（source=job_snapshot）；任务状态另从数据库实时查询（tasks_source=live）。实际请求记录包含技能加载、读取调用和返回结果，可在“本次 skill 与提示词”中查看。测试使用模拟模型，不调用付费服务。

## 输入与引用标签

创作助手使用可多行编辑的富文本输入区。输入 @ 或点击“引用”，可搜索并选择 skill、当前方案的环节和项目资源；↑↓ 选择，Enter/Tab 插入，Esc 关闭候选，Shift+Enter 换行。选中项以可删除标签展示，实际消息使用稳定 token（例如 @skill:director、@stage:director、@asset:资源ID）。skill 标签由后端白名单解析并加载对应 SKILL.md，每条消息最多四个；标签用于明确指定任务，非必填项。环节与资源标签用于强调参考目标，不是读取资料的前置开关。首次发送记录任务所在项目范围，后续切换页面不会把本会话改绑到其他项目。
